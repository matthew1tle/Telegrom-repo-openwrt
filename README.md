# OpenWrt Telegram Bot Panel

A lightweight Telegram bot for OpenWrt routers: system monitoring, network
and Wi-Fi management, client control, package status, config backup/restore,
and threshold alerts - controlled entirely through Telegram's inline
keyboards.

Written in Lua and BusyBox `ash`, using OpenWrt's native `uci`, `ubus`,
`apk`/`opkg`, and `procd` - no Python, Node, or PHP required.

## Directory layout

├── LICENSE

│   ├── helpers.lua             # Shell/JSON/INI-config helpers
│   ├── logger.lua              # Leveled logging with size-based rotation
│   ├── i18n.lua                 # Language loader - see "Adding a language" below
│   ├── state.lua                # In-memory per-chat session state
│   ├── telegram.lua             # Telegram Bot API client (curl-based)
│   └── router.lua               # Auth check + command/callback dispatch
├── keyboards/
│   └── engine.lua               # Inline keyboard builder (all labels via i18n)
├── lang/
│   ├── en.lua                    # English (canonical key set)
│   └── fa.lua                    # Persian
├── modules/
│   ├── system.lua                 # CPU/RAM/flash/uptime
│   ├── monitor.lua                 # Live RX/TX rate

│   ├── clients.lua                   # DHCP leases, client kick
│   ├── wifi.lua                       # Radio/SSID list + toggle

## Install

```sh
cd /tmp
wget -O main.zip https://github.com/matthew1tle/Telegrom-repo-openwrt/archive/refs/heads/main.zip
unzip -o main.zip
cd Telegrom-repo-openwrt-main
chmod +x install.sh
./install.sh
```

You'll need, from Telegram:
- A bot token from **@BotFather** (`/newbot`).
- Your numeric user ID from **@userinfobot** - this becomes the only chat
  ID allowed to use the bot.

`/start` is the only typed command. Every other action - system status,
Wi-Fi, clients, packages, backup/restore, logs, language - is done through
the inline keyboard buttons that `/start` brings up. Typing anything else
just re-shows the menu.

The installer will also ask for a language and a delivery mode (see
below), then start the service. Open your bot in Telegram and send
`/start`.

## Delivery modes: polling vs. webhook

- **polling** (default) - the bot long-polls Telegram for updates. Works
  behind NAT with no public IP, simplest option.
- **webhook** - Telegram pushes updates to a public HTTPS URL you provide
  (e.g. via a reverse proxy or Dynamic DNS + port-forward). Lower idle
  resource use, but needs a reachable HTTPS endpoint. The installer sets
  up a uhttpd CGI handler for you.

You can re-run `install.sh` at any time to switch modes; it backs up the
existing install first.

## Adding a language

Every string in the bot is looked up through `core/i18n.lua`'s `t()`
function - nothing is hardcoded per-file. To add a language:

1. Copy `lang/en.lua` to `lang/<code>.lua` (e.g. `lang/de.lua`) and
   translate the values, keeping the keys unchanged.
2. Set `language="<code>"` in `config.conf`, or use the **Language**
   button in the bot's main menu (it lists whatever's in `lang/`
   automatically).

That's it - no other file needs editing. A translation can also be
partial: any key you don't provide falls back to English automatically.

## Backup and restore

- **Backup / Restore → Backup** from the menu runs `sysupgrade -b` and
  sends you the archive as a Telegram document.
- **Backup / Restore → Restore**, then send the `.tar.gz` file back to the
  bot. It's checked to make sure it's a real sysupgrade archive before
  `sysupgrade -r` is applied. **A reboot is required** afterwards for all
  settings to take effect.

## Alerts

`plugins/alerts.lua` checks CPU load, memory, flash usage, and WAN
reachability on a timer (default: every 60s) and messages every allowed
chat when a threshold is crossed - and again when it recovers. Thresholds
live in `config.conf`'s `[alerts]` section:

```ini
[alerts]
enabled="1"
cpu_percent="90"
mem_percent="90"
disk_percent="90"
check_interval_sec="60"
wan_check_host="1.1.1.1"
```

## Security notes

- `config.conf` contains your bot token in plain text and is `chmod 600`
  by the installer - don't loosen that permission.
- Only chat IDs listed in `allowed_chat_ids` can use the bot; everyone
  else gets a fixed "access denied" reply, and the attempt is logged.
- The bot needs root-equivalent access on the router (it calls `uci`,
  `sysupgrade`, `wifi reload`, etc.) - treat your bot token with the same
  care as a root shell credential. Anyone with the token and your chat ID
  effectively has admin access to the router.
- If you use webhook mode, put it behind HTTPS - Telegram will refuse to
  register a plain-HTTP webhook URL anyway, but make sure the reverse
  proxy in front of it is one you trust.

## Uninstall

```sh
chmod +x /usr/share/owrt-tg-bot/uninstall.sh
/usr/share/owrt-tg-bot/uninstall.sh
```

You'll be asked whether to keep `config.conf` and any backups.

## Update

```sh
/usr/share/owrt-tg-bot/update.sh
```

Backs up the current install first and rolls back automatically if the
update fails partway through.
